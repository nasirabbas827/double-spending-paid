Blockchain Double-Spending Attack Simulator

Abstract / Introduction

Blockchain technology has revolutionized digital transactions by providing a decentralized and immutable ledger system. However, despite its robustness, blockchain networks are vulnerable to various types of attacks, including the double-spending attack.

A double-spending attack occurs when a malicious actor spends the same cryptocurrency more than once before the network confirms the transaction, potentially leading to financial losses. The attacker achieves this by:

  1. Creating a public transaction to send coins to a victim
  2. Simultaneously creating a private transaction sending the same coins to themselves
  3. Mining a private blockchain faster than the honest network
  4. Broadcasting the longer private chain, which reverses the public transaction

This project simulates a double-spending attack on a blockchain system using Python, Flask, and SimPy. It demonstrates how an attacker with sufficient hash power (>51%) can exploit blockchain consensus mechanisms.

Functional Requirements (Implementation)

  1. Blockchain Implementation:
    • Developed a complete blockchain system in Python
    • Implemented blocks, transactions, and proof-of-work (PoW) consensus
    • Transaction validation and balance tracking
  2. Transaction Processing:
    • Transaction validation system with all 6 nodes
    • Majority consensus requirement (4/6 nodes)
    • Transaction broadcasting and verification
  3. Network Simulation:
    • Peer-to-peer (P2P) network with 6 nodes
    • Communication protocol for transaction propagation
    • SimPy-based discrete event simulation
  4. Double-Spending Attack Simulation:
    • Attacker node with private chain mining capability
    • Simultaneous public and private transactions
    • Success rate based on hash rate and network delay
    • CSV logging of all attack attempts with full block details
    • Detailed terminal output for attack visualization
